# SESAME remotes for Ruby Yon projects

These files let a Tachyon Yon project written in Ruby
call SESAME's HTTP API. They follow Tachyon's remotes format: one bodiless
`#[HTTPClient]` contract per route family in `server/remotes/`, one
`SesameSetup` that registers the `sesame` HTTP adapter, and one
`SesameTransportHelper` that sends the requests to SESAME.

The files are generated by `go run ./tools/remotes/generate` from
[`api/machine/v1/operations.json`](../../api/machine/v1/operations.json). Do
not edit them here: change `tools/remotes/templates/ruby/` and run the
generator again.

## Requirements

- `ty` 26.36.01 (commit `a7ccbfff`) or later.
- A SESAME Yon host behind HTTPS (see [docs/YON.md](../../docs/YON.md)).

## Copy them into your project

```bash
cp -R remotes/ruby/server/. /path/to/your-project/server/
```

This adds `server/remotes/Sesame*Client.rb`, `server/setups/SesameSetup.rb`
and `server/helpers/SesameTransportHelper.rb`.

## Configure

Add these members to `server/application.json`:

```json
{
  "outgoing": { "hosts": ["sesame.example.com"] },
  "sesame": { "origin": "https://sesame.example.com" },
  "names": { "words": ["authn", "deprovision", "dpop", "jwks", "oidc", "saml", "scim", "totp"] }
}
```

- `sesame.origin`, or `YON_SESAME_ORIGIN` in the project's `.env`: SESAME's
  public origin, the scheme, host and optional port. It must be `https`, with
  no path, query, fragment or user name. Plain `http` is accepted only for
  `localhost`, `127.0.0.1` and `::1`, for development. With any other value
  every call fails.
- `outgoing.hosts`: SESAME's host name, without scheme or port. Tachyon sends
  outgoing requests through a guard that refuses every host not in this list
  (Tachyon ADR 0068), so without it every call fails. For a local SESAME, list
  `127.0.0.1`.
- `names.words`: the remote class and method names use these SESAME
  words, and Tachyon's name check (`TY1328`) refuses them otherwise.

## Call SESAME

Inject a remote into a service with `Needs`:

```ruby
#[Service]
class SignInService
  #[Needs]
  # @return [SesameAuthnClient]
  attr_reader :sesame_authn_client

  # @param tenant_id [String]
  # @param email [String]
  # @return [Hash]
  def sign_in(tenant_id, email)
    sesame_authn_client.begin(
      { "tenant_id" => tenant_id, "identifier_namespace" => "email", "identifier_value" => email }
    )
  end
end
```

Bodies and answers are JSON values (`Hash`, `Array`, `String`, numbers,
`true`, `false`, `nil`). Tachyon does not decode them into types, so check the
fields you read. The request bodies are the operation parameters described in
[docs/YON.md](../../docs/YON.md) and [api/machine/v1](../../api/machine/v1/README.md).
Every `POST` method takes a body: send `{}` when the route reads no fields.

## Authentication headers

- A method for a `signed_in` or `administrator` route takes `session` first,
  as a `String`. Pass `"<session_id>:<session_secret>"` of the person
  your application acts for; it is sent as the `Sesame-Session` header.
- A method for a SCIM provisioning route (`scim/user-*`, `scim/group-*`) takes
  `authorization` first. Pass `"Bearer <token>"`; it is sent as the
  `Authorization` header.
- Methods for `public` routes take no header.

Never log these values and never put them in a path or a query. An empty
string sends an empty header, and SESAME answers `401`.

## Answers and errors

Every method answers `{"status": <HTTP status>, "body": <JSON body or null>}`.
Check `status` before you read `body`:

- `2xx`: `body` is SESAME's result.
- SESAME's own refusals: `body` is `{"code": "<code>"}`, with the status from
  the table in [docs/YON.md](../../docs/YON.md#errors) (`400`, `401`, `403`,
  `404`, `409`, `503` for `engine_busy`: retry later, `500` for
  `internal_error`).
- The route guard of SESAME's `ty` answers `401`, `403` and `500` as plain
  text, so `body` is `null`.
- `ty`'s request checks answer `400` with `{"error", "field", "part"}`.

The call itself fails with Tachyon's `BehaviorError` (code `adapter`) when `sesame.origin` is missing or not allowed, the network
fails, the deadline passes, SESAME answers with a redirect (never followed),
or the answer is larger than 1 MiB. Tachyon hides the cause on purpose. With a
plain `http` loopback origin in development, a host missing from
`outgoing.hosts` answers `403` from Tachyon's guard instead.

The helper uses `Net::HTTP` from Ruby's standard library. `Net::HTTP` never sends a
loopback address through a proxy, so the helper reads Tachyon's
`HTTPS_PROXY` (for `https`) or `http_proxy` (for `http`) and sends every
request through it.

## What the remotes do not cover

- Standard endpoints: only `GET /oidc/openid-configuration` and
  `GET /oidc/jwks` (`SesameStandardsClient`). `/oidc/authorize` and
  `/oidc/logout` are browser redirects, and `/oidc/token`, `/oidc/introspect`
  and `/oidc/revoke` take form-encoded bodies, which a Tachyon remote cannot
  send. Use an OAuth 2.0 and OpenID Connect client library with the discovery
  document for them.
- `oidc/interaction-get` and `oidc/interaction-complete` read the browser's
  `__Secure-sesame_interaction` cookie. Tachyon refuses a `Cookie` header in a
  remote, so through a remote they answer as if the cookie were missing. Call
  them from the browser.
- Operations that SESAME never serves over HTTP: `tenant.bootstrap` and
  `admin.bootstrap` (command line only) and `federation.login_exchange`.
