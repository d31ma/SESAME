Every release ships native binaries, an SPDX SBOM, checksums, and build provenance. This is a developer preview: it is not supported for production use, and no release has passed an independent security review.

Install from source

The shortest path if you already have Go 1.26.

go install github.com/d31ma/sesame/cmd/sesame@latest

Release binaries

Cross-compiled artifacts are published on every tag. A binary built for a platform is not the same as support for it: SESAME claims a platform only with native packaging, crash, restore, and upgrade evidence run on that operating system.

Reaching SESAME

Any language calls the HTTP API of SESAME's Yon host, which the repository root serves with ty serve. Go applications can start the engine themselves with the standard-library-only Go package, resolved at the release commit. The language shims of earlier releases are retired. 

go get github.com/d31ma/sesame/server/packages@<commit>

Distribution records how each former SDK language moves to the HTTP API or the machine protocol, and how a release is verified.

Verify what you downloaded

Every release is attested with build provenance. Check it before you run it, and check every subject in the attestation rather than the first one — one statement covers all of a release's assets. 

shasum -a 256 -c SHA256SUMS
gh attestation verify sesame-linux-amd64 --repo d31ma/sesame

You also need FYLO

SESAME stores every authoritative record in FYLO and drives it as a subprocess. Install a FYLO runtime for your platform, then point sesame init at the binary. sesame doctor verifies the runtime version and build target and refuses a mismatch.
