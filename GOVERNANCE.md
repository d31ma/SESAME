# SESAME Governance

SESAME uses maintainer-led, consensus-seeking governance.

## Roles

- **Contributors** propose changes, report issues, improve documentation, and
  participate in review.
- **Maintainers** merge changes, manage releases, triage security reports, and
  protect compatibility and project scope.
- **Security maintainers** may coordinate embargoed fixes and disclosure.

Maintainer status is earned through sustained, technically sound contributions,
constructive review, and demonstrated care for security and community health.
Existing maintainers approve additions or removals by consensus.

## Decisions

- Routine changes use pull-request review.
- Hard-to-reverse architecture decisions require an ADR.
- New public behavior or compatibility policy requires an RFC.
- Security embargoes may temporarily limit discussion and access.
- If consensus cannot be reached, maintainers document the competing options
  and rationale for the final decision.

## Open-Source Boundary

Emergency revocation, authentication hardening, MFA/passkeys, audit export,
backup/restore, and supported protocol security controls remain available in
the Apache-2.0 distribution. Commercial hosting or support must not weaken that
baseline.

## Changes to Governance

Governance changes use the same public review process and must preserve an
auditable history.
